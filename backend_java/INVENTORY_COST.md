# Inventory and cost model — V008

See [the handover](../V008_HANDOVER.md) for migration, test results and recovery instructions. V001–V007 are prerequisites; never rerun schema.sql/sample_data.sql on existing data.

- Each immutable PRODUCT_DETAIL ID has PHYSICAL_QUANTITY, RESERVED_QUANTITY and QUANTITY (available). Available = physical − reserved; a database constraint rejects inconsistencies.
- Order creation reserves atomically without changing physical quantity or cost. Pre-dispatch cancellation releases the reservation once. Staff can prepare a DISPATCH draft; only ADMIN approval reduces physical and reserved by the same quantity and changes the order to shipping. Failed delivery never automatically restores stock.
- PRODUCT_DETAIL.AVERAGE_COST is the moving average for that SKU's physical stock, including held stock. PRODUCT.AVERAGE_COST is obsolete historical evidence, never a source for per-SKU valuation.
- Receipts recalculate `(existing physical value + receipt quantity × receipt cost) / new physical quantity`. Internal cost/value arithmetic uses BigDecimal/NUMBER with 8 decimals. Snapshot sale COGS at actual dispatch; subsequent receipts cannot change it.
- Unknown cost is NULL, not zero. UNKNOWN_QUANTITY and KNOWN_VALUE retain the incomplete/known portions. A fully documented zero-cost receipt remains known. Physical quantity zero always has zero value. New documented receipts are retained even when old stock lacks costs; valuation remains incomplete. For issues from mixed unknown stock, known/unknown portions are reduced proportionally without certifying a full unit cost.
- Product inventory value is the sum of its SKU values; warehouse totals count each SKU once over every matching page. All displayed SKU monetary values use whole-VND HALF_UP rounding before aggregation, while averages remain precise internally. Available-stock value is labeled separately.
- Sellable returns restore the dispatch cost of the original line. Damaged returns never enter available stock; their expense is separated from COGS. Returns cannot exceed dispatched quantities. Return COGS, discounts and shipping use cumulative/remainder allocations so details sum to their totals.
- A stock count compares physical quantity, held quantity and STOCK_VERSION with the draft snapshot. It cannot consume reserved stock; positive differences require documentary cost or remain explicitly unpriced. Reversals link to their source and reject subsequent movements or incompatible balances. Reversing a return is blocked after pending/paid refunds.
- Revenue is recognized on completion, return reductions on posting and return-reversal adjustments on posting the reversal. Shipping is separate. Manual refund payments have their own pending/paid/failed records, references and operators, and never reduce revenue again.
- ADMIN can reconcile a SKU's current balance with reason, evidence and expected physical quantity, even after sales/issues. Preview states that historical sales are not changed. Cost adjustments leave quantities unchanged and write before/after audit values. Historical missing COGS remains unknown until specifically reconstructed from evidence.
- V008 reconstruction replays documented SKU receipts/dispatches/returns; it never assigns a pooled product cost to a SKU. Legacy AVAILABLE_LEGACY movement dates cannot certify physical opening/closing balances and are flagged in reports.
